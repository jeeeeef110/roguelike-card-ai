# GDD:Roguelike 卡牌構築遊戲(APCS 備審專案)

## 一、專案定位

- **專案名稱**:(暫定)待命名
- **類型**:單機 Roguelike 卡牌構築(DBG)+ 局外養成
- **平台**:PC(Godot 4)
- **核心賣點(備審視角)**:會思考的 AI 對手(MCTS)+ 蒙地卡羅模擬驅動的數值平衡
- **一句話描述**:玩家在隨機生成的地圖中戰鬥、構築牌組、養成角色,對抗使用搜尋演算法決策的 AI 敵人。

## 二、核心循環

```
選擇地圖節點 → 卡牌對戰 / 事件 / 商店 → 獲得卡牌與資源
→ 強化牌組 → 挑戰頭目 → 局外養成(解鎖角色/卡池)→ 下一輪
```

## 三、系統設計

### 3.1 戰鬥系統(演算法主戰場)

- 回合制,玩家與敵人輪流出牌
- 資源:每回合固定能量(3 點),卡牌消耗能量
- 卡牌類型:攻擊 / 防禦 / 技能(buff、抽牌、能量操作)
- 狀態效果:中毒、易傷、護甲、力量(各 1 種即可,先求少)

**AI 對手決策(核心技術點)**:
- 第一版:規則式 AI(基準線,用來對照)
- 第二版:Expectimax(處理抽牌隨機性,深度 2-3 層)
- 第三版:MCTS(蒙地卡羅樹搜尋,含 UCB1 選擇策略)
- 面試素材:三版 AI 互打的勝率對照表

### 3.2 牌組構築系統

- 起始牌組 10 張,戰鬥後三選一加牌,商店可刪牌
- **卡牌協同評分**:實作一個評估函數,計算「候選卡加入現有牌組的期望價值」
  - 特徵:能量曲線、攻防比例、combo 觸發率
  - 用途:AI 敵人構築牌組 + 玩家端「推薦卡牌」提示
- 面試素材:貪婪選卡 vs 全域最佳化的取捨討論

### 3.3 地圖生成(程序化生成)

- 節點式地圖(類殺戮尖塔):15 層,每層 2-4 個節點
- 加權隨機 + 約束條件(商店不連續出現、頭目前必有休息點)
- 演算法:分層 DAG 生成 + 路徑連通性檢查

### 3.4 養成系統(局外)

- 貨幣:每局結算獲得「靈魂碎片」
- 用途:解鎖新角色(2-3 個,不同起始牌組)、擴充卡池、永久小幅加成
- 存檔:JSON 本地存檔即可

### 3.5 平衡性分析(大加分項)

- 寫 headless 模擬腳本:AI vs AI 自動對打 1000+ 場
- 統計:各卡牌採用率、勝率貢獻、平均戰鬥回合數
- 用數據迭代卡牌數值,並保留調整前後的對照圖表
- 面試素材:「我用蒙地卡羅模擬做遊戲平衡」+ 圖表

## 四、內容範圍(最小可行版本 MVP)

| 項目 | MVP 數量 | 完整版目標 |
|------|---------|-----------|
| 可玩角色 | 1 | 3 |
| 卡牌 | 30 | 60 |
| 一般敵人 | 3 | 8 |
| 菁英/頭目 | 1 | 3 |
| 地圖層數 | 10 | 15 |
| 狀態效果 | 4 | 8 |

**原則:先把 MVP 做完並讓 AI 會玩,再擴充內容。**

## 五、技術架構

- **引擎**:Godot 4(GDScript)
- **核心邏輯與引擎分離**:戰鬥規則、AI、模擬器寫成純邏輯層(不依賴節點系統),方便 headless 跑模擬,也是面試講架構的亮點
- **版本控制**:GitHub,commit 訊息認真寫,README 記錄設計決策與失敗嘗試
- **測試**:核心規則寫單元測試(出牌合法性、傷害計算)

## 六、開發時程(2026/07 → 2027/04)

### 第一階段:核心戰鬥(7月–8月中,6 週)

### 第二階段:AI 與生成(8月中–9月底,6 週)

- W9-10:MCTS AI + 三版 AI 對打數據

### 第三階段:養成與平衡(10月–11月,6 週)
- W13-14:局外養成、存檔系統
- W15-16:headless 模擬器 + 平衡數據收集

### 第四階段:學測衝刺(12月–1月)
- **停止開發**,只維持 repo 整潔。全力準備學測。

### 第五階段:備審整理(2月–3月)
- 內容小幅擴充(第二角色、卡池)
- 撰寫專案報告:架構圖、AI 演算法說明、平衡分析圖表
- 準備面試 QA:每個技術決策都要能答「為什麼這樣做、還試過什麼」

## 七、風險與退路

- **進度落後**:優先砍內容量(卡牌、敵人數),絕不砍 AI 和模擬器——那是備審的靈魂
- **MCTS 做不出來**:退守 Expectimax,一樣有東西可講
- **Godot 卡關**:退守 Python + Pygame 甚至純終端介面,教授不在乎畫面

## 八、備審敘事主軸(先想好結局)

書審報告的故事線:
1. 動機:想做一個「AI 會思考」的卡牌遊戲
2. 挑戰一:隨機性下的決策 → Expectimax → MCTS 演進

5. 反思:取捨與未竟之處(誠實寫,教授吃這套)
