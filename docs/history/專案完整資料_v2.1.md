## 一、專案定位

- **類型**:單機 Roguelike 卡牌構築(DBG)+ 局外養成
- **技術棧**:Python 3 單一程式碼庫(core 純邏輯 / Pygame UI / headless 模擬器)
- **開發者**:Jeff(高中生,APCS 4+4,目標大學申請備審)
- **核心賣點(備審視角)**:
  1. MCTS 玩家代理:隨機抽牌下的決策(determinization),兼遊戲內出牌建議與模擬器引擎
  2. 蒙地卡羅模擬驅動數值平衡,含 A/B 對照實驗
  3. core/ui/sim 分層架構:一套規則引擎同時支撐遊戲與模擬

## 二、已定案的關鍵設計決策(不可推翻)

1. 敵人為**腳本化意圖制**(加權狀態機),不持有牌組——複雜度放在玩家側 AI
2. 代理三版演進並保留對照:規則式 → Expectimax → MCTS+UCB1
3. core 層零外部依賴、完全確定性(RNG 注入 seed,同 seed 可重播)
4. 選卡評估:啟發式評分 + 模擬驗證兩層(不用 DP,此問題無最佳子結構)
5. 平衡分析用 A/B 對照實驗(固定代理與基準牌組、單一變因換卡),不直接統計卡牌勝率(有混淆變數)
6. **不做**:遺物系統、詛咒/狀態卡、多幕結構(MVP 為 1 幕)——控制範圍

## 三、戰鬥規則(已定案,參考殺戮尖塔)

### 3.1 回合結構
- 回合開始:抽 5 張、能量回滿 3 點、格擋歸零
- 出牌階段:張數不限,只受能量限制
- 回合結束:手牌全部棄掉 → 敵人執行已宣告的意圖 → 進入下一回合
- 牌庫抽完時,棄牌堆洗回牌庫(用注入的 RNG)

### 3.2 卡牌
- 屬性:名稱 / 能量費用 / 類型 / 效果列表
- 類型:攻擊、技能(能力型永久生效卡延後,不進 MVP)
- 效果以資料表示(如 `{type: damage, value: 8, target: enemy}`),加卡不改引擎
- 起始牌組 10 張:5 攻擊(6 傷)+ 4 防禦(5 甲)+ 1 技能(暫定:抽 2 張)

### 3.3 狀態效果(MVP 四種,精確機制)
| 狀態 | 機制 | 持續 |
|------|------|------|
| 護甲(格擋) | 抵銷等量傷害 | 回合開始歸零 |
| 力量 | 每層攻擊 +1 | 永久(該場戰鬥) |
| 易傷 | 受到傷害 ×1.5(向下取整) | N 回合,每回合 -1 |
| 中毒 | 回合開始扣層數等量 HP,無視護甲 | 每回合層數 -1 |

### 3.4 敵人:意圖系統
- 敵人不出牌;每回合開始宣告意圖(圖示+數值公開),回合結束執行
- 行為模式為加權狀態機,MVP 三隻(數值為初始值,待模擬器調整):
  - **巨鼠**(HP 28):60% 攻擊 6 / 40% 蓄力(下回合必攻擊 12)
  - **毒蛛**(HP 22):50% 攻擊 4+中毒 2 / 30% 中毒 3 / 20% 護甲 6
  - **石像兵**(HP 40):循環固定序列:護甲 8 → 攻擊 9 → 攻擊 9(可預測,教玩家讀意圖)
- 頭目 ×1(HP 90,階段制:HP<50% 切換攻擊模式,細節待設計)

### 3.5 第一批卡牌清單(15 張,數值為初始值)
| 卡名 | 費 | 效果 |
|------|----|------|
| 打擊 | 1 | 傷害 6 |
| 防禦 | 1 | 護甲 5 |
| 重擊 | 2 | 傷害 8 + 易傷 2 |
| 順勢斬 | 1 | 傷害 4,若敵有易傷再 +4 |
| 毒刃 | 1 | 傷害 3 + 中毒 2 |
| 猛毒 | 1 | 中毒 4 |
| 鐵壁 | 2 | 護甲 11 |
| 反甲擊 | 1 | 傷害 = 目前護甲值 |
| 蓄力 | 1 | 力量 +2 |
| 狂暴 | 0 | 傷害 3,抽 1 張 |
| 兵法 | 1 | 抽 2 張 |
| 充能 | 0 | 能量 +1,本回合手牌上限內棄 1 張 |
| 連擊 | 1 | 傷害 3 ×2 次 |
| 破甲 | 1 | 移除敵方護甲,傷害 5 |
| 背水 | 2 | 傷害 14,自身受 3 傷 |
（其餘 10 張待引擎完成後補齊至 MVP 25 張）

## 四、關卡與流程

### 4.1 核心循環
```
選擇地圖節點 → 戰鬥 / 事件 / 商店 → 三選一加牌 + 金幣
→ 強化牌組 → 頭目 → 局外養成(靈魂碎片)→ 下一輪
```

### 4.2 地圖(MVP:1 幕 10 層)
- 分層 DAG,每層 2–4 節點,只能走有連線的節點
- 節點類型:一般敵人、休息點(回血 30% 或升級延後→MVP 只回血)、商店(買卡/刪卡)、問號事件
- 生成約束:第 1 層必為一般敵人、第 9 層必為休息點、第 10 層為頭目、商店不連續出現
- 演算法:加權隨機 + 約束 + 連通性檢查

### 4.3 養成(局外,第三階段才做)
- 每局結算獲得靈魂碎片 → 解鎖角色(不同起始牌組)、擴充卡池、永久小幅加成
- JSON 本地存檔

## 五、AI 系統

### 5.1 MCTS 玩家代理(演算法主戰場)
- 用途:遊戲內「出牌建議」(顯示最佳動作+勝率估計)+ 模擬器引擎
- 演進路線:
  1. 規則式(基準:優先擋致死傷害,再最大化輸出)
  2. Expectimax(深度 2–3,機率節點取樣)
  3. MCTS + UCB1(determinization:每次 rollout 洗一副假想牌庫)
- 面試素材:三版在固定敵人配置下的勝率對照 + 決策時間比較

### 5.2 選卡評估
- 第一層:啟發式(能量曲線、攻防比、combo 觸發率)
- 第二層:模擬驗證(候選卡入組後跑 N 場比勝率)
- 面試素材:快而近似 vs 準而昂貴的取捨、兩者結論不一致的案例

### 5.3 平衡模擬(sim 層)
- headless:MCTS 代理自動打完整局 1000+ 場
- 統計:卡牌採用率、平均回合數、各層存活率
- A/B 對照實驗歸因卡牌強度;保留調整前後圖表(matplotlib)

## 七、技術架構

```
project/
├── core/     # GameState、卡牌效果、敵人意圖、戰鬥流程。零依賴、seed 可重現
├── agents/   # rule_based / expectimax / mcts,統一介面 Agent.choose_action(state)
├── ui/       # Pygame,只呼叫 core 公開 API
├── sim/      # 模擬器、A/B 實驗、統計輸出
└── tests/    # pytest
```
- ui/sim 不直接改 core 內部狀態;core 不 import pygame、不 print(回傳事件列表)
- GitHub 管理,commit 格式 `[模組] 做了什麼`,README 記錄設計決策與失敗嘗試
